## Purpose

Role Fit estimates whether the candidate’s **professional function, seniority, and ownership pattern** match the opportunity — independent of a single tool checkbox.

## Criteria

| Criterion | What to look for |
|-----------|------------------|
| Similar function | Architect vs developer vs analyst vs support |
| Seniority | Scope of decisions, not title alone |
| Ownership | Owned architecture / delivery vs assisted |
| Technical leadership | Mentoring, standards, guilds, tech lead acts |
| Architectural decisions | Trade-offs, target architecture, ADRs |
| Architecture practice | Patterns, governance, cross-system design |
| End-to-end | Discovery → design → delivery → ops awareness |
| Complexity | Enterprise scale, multi-system, regulated |
| Stakeholders | Client, vendors, security, business, multi-teams |

## Positive examples

- “Solution architect responsible for integration target architecture across SAP and cloud platforms.”
- “Tech lead defining API standards and reviewing integration designs.”
- “Owned modernization roadmap from SAP PO to a cloud iPaaS with multi-team coordination.”

## Negative / weak examples

- Title says “Architect” but evidence is only ticket-level coding with no design ownership.
- Strong hands-on OIC developer with no architecture/stakeholder scope for an architect JD.
- “Participated in meetings” without decision accountability.

## Anti-patterns

- Inferring seniority only from job title.
- Equating years-in-company with architectural ownership.
- Treating tool expertise as automatic Role Fit for an architect vacancy (or vice versa).

## Output guidance

Provide a qualitative Role Fit assessment plus, when scoring, a 0–100 contribution consistent with methodology weights. Call out interview probes when ownership is ambiguous.
